# 修仙问道 · 放置挂机

一个以修仙成长为主题的浏览器放置挂机小游戏。玩家从练气期起步，通过打坐、功法、炼体、经营、征战、宗门和轮回等系统不断积累资源，突破境界，探索完整仙途。

## 项目简介

《修仙问道》采用原生 HTML、CSS 和 JavaScript 构建前端界面，使用 Node.js 与 Express 提供静态资源服务及云端存档 API。项目无需数据库即可运行，适合本地体验、个人部署和继续扩展。

项目特点：

- 浏览器即开即玩，无需前端构建工具
- 放置收益与主动操作并存
- 多阶段境界成长和突破机制
- 丰富的资源、装备、功法和养成系统
- 本地存档、JSON 导入导出和服务端存档备份
- 响应式深色修仙主题界面
- 纯 JavaScript 实现，结构直观，方便二次开发

## 游戏系统

### 修炼与境界

- 打坐修炼：持续积累修为，并支持挂机收益
- 境界突破：修为达到要求后尝试突破，成功率受多种属性影响
- 心魔：修炼和突破过程中的风险资源，需要通过玩法和道侣等方式控制
- 灵石：用于功法、洞府、炼体、阵法和各类经营操作
- 离线收益：再次进入游戏时结算离线期间的修炼与资源收益

### 灵根与体质

灵根和体质决定角色的基础成长方向。轮回后可以洗练灵根与体质，获得更高品阶和更强的长期成长倍率。

### 功法秘典

玩家可以参悟和升级功法，获得修炼速度、灵石产出或突破成功率等加成。当前功法体系包含：

- 天衍诀
- 玉清剑诀
- 太清心经
- 混元道典

不同功法拥有境界和灵石解锁条件，形成持续的成长目标。

### 悟道神通

悟道神通使用悟道点进行升级。悟道点主要来自成功突破和轮回转世，可用于强化：

- 汲灵：提升修炼速度
- 聚财：提升灵石产出
- 悟道：提升突破成功率
- 云游：提升云游收益
- 丹心：提升炼丹产量
- 冶金：提升精铁掉落

### 炼体

通过消耗灵石淬炼肉身，积累体修进度并进行肉身突破。炼体境界会提升角色战力，并对突破能力产生帮助。

### 经营与资源生产

经营系统集中在“经营”标签页，包含：

- 洞府：扩建洞府，提升整体资源产出
- 灵田：开辟田地、播种和收获灵草
- 丹药坊：使用丹药获得临时或长期帮助
- 炼丹炉：依照丹方炼制丹药
- 云游历练：通过不同历练获取灵石、灵草、精铁和其他奖励
- 坊市：购买和出售资源，利用每日随机折扣
- 拍卖行：定期刷新可竞拍的法器和灵材

### 征战与战力

征战系统围绕战力和战利品展开：

- 法宝：收集并淬炼法宝，提升角色能力
- 战斗历练：挑战镇妖塔，逐层获得奖励
- 妖王：讨伐强敌，检验当前战力
- 秘境试炼：消耗精力挑战秘境，获取成长材料
- 宗门大比：与敌对宗门交战，获取贡献、威望、灵石和精铁

### 宗门、弟子与道侣

- 加入宗门，获得宗门加成
- 捐献资源、升级宗门科技和学习宗门技能
- 招收并培养弟子，获得额外辅助效果
- 结识道侣并进行双修，提升修为并平息心魔
- 参与宗门驻地和周期性赛事，积累战功并领取结算奖励

### 符箓与阵法

符箓提供限时增益，阵法提供持续增益：

- 聚灵符：短时间提高修炼速度
- 破境符：增加多次突破成功率
- 护体符：短时间提升战力
- 聚财符：短时间提高灵石产出
- 聚灵阵：持续提升修炼速度
- 聚财阵：持续提升灵石产出
- 玄甲阵：持续提升突破成功率
- 天罡阵：持续提升战力

### 轮回与传承

轮回转世是项目的长期成长核心。完成轮回后，玩家可以获得传承点和新的成长起点，并通过传承道纹永久强化后续周目。

传承方向包括修炼速度、灵石产出、突破成功率、战力、洞府、炼丹、精铁掉落和妖王战利等。

### 仙界

渡过天劫后进入仙界，解锁新的境界、仙器、仙兽、仙术、仙府、仙界塔和跨服榜等后期内容。

### 日常、成就与图鉴

- 每日签到和连续签到奖励
- 成就系统，记录关键成长节点
- 图鉴系统，记录已发现的角色、资源、法宝和事件
- 奇遇事件，根据玩家选择产生不同结果
- 玩法速览，随时查看各系统的解锁条件和说明

## 操作说明

1. 点击“打坐修炼”或等待挂机收益积累修为。
2. 修为达到要求后，点击“突破境界”。
3. 使用灵石参悟功法、淬炼肉身、扩建洞府和升级阵法。
4. 通过经营系统生产灵草、炼制丹药并积累资源。
5. 进入征战系统挑战秘境、镇妖塔和妖王。
6. 解锁宗门、弟子、道侣等系统，获得额外加成。
7. 达到条件后进行轮回，利用传承点强化后续周目。
8. 使用“存档”保存进度，也可以导出 JSON 文件进行备份。

- Node.js 18 或更高版本

```text
http://localhost:3000
```

```bash

```

## 存档机制

项目同时支持浏览器端和服务端两类存档方式：

- “存档”：将当前进度保存到服务端
- “导出”：下载 JSON 存档文件
- “导入”：从 JSON 文件恢复进度
- “重置”：清理当前游戏进度，并尝试删除服务端备份
- 自动保存：游戏运行过程中按客户端逻辑保存进度
- 离线结算：重新打开游戏时根据离开时间计算收益

服务端存档接口：

```text
GET    /api/save?pid=<player-id>
POST   /api/save
DELETE /api/save?pid=<player-id>
```

服务端会校验玩家 ID 格式、存档版本和存档体积，并通过临时文件重命名方式写入存档，减少写入中断造成的文件损坏风险。

`server/data/` 下的运行时存档不会提交到 GitHub，项目已通过 `.gitignore` 忽略 `save_*.json` 文件。

## 部署方式

### Node.js 服务器

将项目复制到目标服务器后执行：

```bash
npm install --production
npm start
```

建议使用进程管理器或系统服务保持 Node.js 进程运行，并通过反向代理提供 HTTPS 访问。

### 反向代理注意事项

如果部署在 Nginx、Caddy 或其他反向代理之后：

- 将代理请求转发到 Node.js 服务端口
- 保留 `GET`、`POST` 和 `DELETE` 请求方法
- 允许 `/api/save` 接收至少 1 MB 的 JSON 请求体
- 为 `server/data/` 配置持久化磁盘
- 不要将 `.env`、存档文件或运行时目录公开为静态资源

## 安全设计

- 玩家 ID 只允许字母、数字、下划线和连字符
- 存档路径由服务端生成，避免路径穿越
- JSON 请求体限制为 1 MB
- 单个存档序列化后限制在 900 KB 内
- 存档版本不匹配时拒绝覆盖
- `.env`、密钥、证书和本地存档不会提交到仓库
- 服务端静态目录仅暴露 `public/` 内容

## 开发建议

修改游戏规则时，主要关注：

- `public/js/game.js`：状态字段、资源计算、定时循环、玩法逻辑和存档数据
- `public/js/ui.js`：各系统的 DOM 渲染、按钮事件和弹窗交互
- `public/index.html`：页面结构、面板和系统入口
- `public/css/style.css`：视觉样式、布局和移动端适配
- `server/server.js`：静态资源服务和云端存档接口

新增游戏系统时，建议同步完善状态初始化、状态保存与恢复、界面渲染、按钮事件、解锁条件和玩法速览，避免刷新或轮回后数据不一致。
